# Failure cases and how they were checked

Each case says what the system does and how that was verified: an **automated test** (runs with
`docker compose run --rm test`), **checked by hand** (in the running stack, on the date given), or **not verified**.
All hand checks so far ran on Windows with Docker Desktop.

## Step 1: skeleton

| Case                                                              | What happens                                                                                                                                     | Verified                                                                                                                                                                                       |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Postgres drops a connection the pool holds idle                   | The broken client is discarded; once the pool has reported it, the next query opens a new one (a query sent in that moment can still fail)       | Automated test (`db.test.ts`); fails without the handler                                                                                                                                       |
| Postgres drops a connection the app is holding, idle or mid-query | The query in flight fails; later queries get new connections                                                                                     | Automated tests (`db.test.ts`): a held connection and a query in flight; all three connection tests fail without the listener                                                                  |
| Redis is down                                                     | `/ready` answers 503 naming Redis; commands fail at once rather than queueing                                                                    | Automated test with an unconnected client. By hand, 2026-11-24: Redis stopped, 503, back to 200 about 3 s after Redis returned                                                                 |
| A dependency hangs without answering                              | `/ready` gives up after about 2 s and answers 503                                                                                                | Automated test (a Redis stub that never answers)                                                                                                                                               |
| Postgres stops while the API runs                                 | The API stays up; `/ready` answers 503 naming the database                                                                                       | By hand, 2026-11-24: no restart, back to 200 about 1 s after Postgres returned                                                                                                                 |
| Postgres unreachable when the API starts                          | The migration fails, the API logs the reason (no credentials) and exits with code 1; Docker restarts it                                          | By hand, 2026-11-24 (exit code 1 and the log line). Docker's restart back-off not verified                                                                                                     |
| A stop request while start-up is blocked on the migration lock    | One shutdown once the statement in flight ends (at most 15 s, inside the 20 s stop grace period), exit code 0                                    | By hand, 2026-11-24: `docker compose stop api` with the lock held from another session stopped after 13 s, exit 0. Before the 20 s grace period, Docker killed it after about 3 s (exit 137)   |
| `docker compose stop api` while serving                           | Logs the shutdown, closes connections, exit code 0                                                                                               | By hand, 2026-11-24                                                                                                                                                                            |
| First start on an empty volume                                    | Postgres reports healthy only once it accepts TCP connections, so dependants don't start early                                                   | By hand, 2026-11-24, on a throwaway Compose project                                                                                                                                            |
| Postgres and Redis restart with reduced capabilities              | Both start and restart normally                                                                                                                  | By hand, 2026-11-24: fresh volumes plus two restarts. Without `DAC_OVERRIDE` Redis fails every restart; with no capabilities Postgres fails its first start ("failed switching to 'postgres'") |
| Two services run migrations at the same moment                    | Kysely's migrator holds a Postgres advisory lock, so they run one after the other; a service that waits more than 15 s gives up and is restarted | Not verified; read in Kysely's source                                                                                                                                                          |
| Embeddings of different sizes in one table                        | Stored side by side; each document searched with its own size                                                                                    | Automated test (768, 1,536 and 3,072 dimensions)                                                                                                                                               |
| The test command after a code change                              | The test image rebuilds, so the new code is what runs                                                                                            | By hand, 2026-11-24: a test file added and removed without `--build`                                                                                                                           |
| Tests pointed at a database not named `*_test`                    | The test setup refuses to run                                                                                                                    | Not verified by a test; a guard in `test/global-setup.ts`                                                                                                                                      |
| Linux or macOS host                                               | Expected to behave the same                                                                                                                      | Not verified (no CI)                                                                                                                                                                           |

## Step 2: upload, preparation and answers

| Case                                                                                                                                                 | What happens                                                                                                                                       | Verified                                                                                                                                                 |
| ---------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Empty file, binary file (NUL bytes), UTF-16, invalid UTF-8, a PDF, a file over 1 MB                                                                  | Refused with 400, 413 or 415 and a fixed code; no document row is left                                                                             | Automated tests (`flow.test.ts`)                                                                                                                         |
| A body that isn't multipart, has no boundary, or is cut off                                                                                          | 415 `unsupported_type` or 400 `invalid_request`                                                                                                    | Automated test                                                                                                                                           |
| A question holding a NUL character                                                                                                                   | 400 `invalid_request`                                                                                                                              | Automated test                                                                                                                                           |
| Windows line endings, a UTF-8 byte-order mark                                                                                                        | Stored as LF without the mark, so offsets match the stored text                                                                                    | Automated test                                                                                                                                           |
| A file with headings and no text                                                                                                                     | The document ends `failed` with `empty_document`                                                                                                   | Automated test                                                                                                                                           |
| An indented line longer than a chunk, emoji at a hard cut                                                                                            | No empty chunk and no split emoji; every chunk is an exact slice                                                                                   | Automated tests (`text.test.ts`)                                                                                                                         |
| Thousands of one-line sections (a glossary)                                                                                                          | Short sections are packed together: 2,000 sections make fewer than 200 chunks                                                                      | Automated test                                                                                                                                           |
| A short section followed by thousands of blank lines                                                                                                 | Packing stops at the target size, so no chunk passes 1,600 characters                                                                              | Automated test                                                                                                                                           |
| A heading-like line longer than 200 characters (say 160,000 spaces or `#`)                                                                           | Treated as a paragraph; chunked in milliseconds                                                                                                    | Automated test                                                                                                                                           |
| Headings such as `# C#` and `## Results ##`                                                                                                          | The title keeps its own `#` and drops the closing run                                                                                              | Automated test                                                                                                                                           |
| A document with 1,200 chunks                                                                                                                         | Prepared in one transaction, 500 rows per insert statement                                                                                         | Automated test (the batch size itself isn't checked)                                                                                                     |
| A document that would make more than 5,000 chunks                                                                                                    | `failed` with `too_many_passages`, before any embedding call                                                                                       | Automated test                                                                                                                                           |
| A preparation job for a document that is gone, already ready, or on a newer attempt                                                                  | Does nothing                                                                                                                                       | Automated test                                                                                                                                           |
| Preparation run again after a crash left chunks behind                                                                                               | Deletes them and writes the full set again                                                                                                         | Automated test                                                                                                                                           |
| While a preparation job is embedding, a newer attempt claims the row or the row is marked failed                                                     | The old job's chunks and its `ready` are rolled back                                                                                               | Automated tests, one per guard condition                                                                                                                 |
| Embedding model down while preparing                                                                                                                 | The job runs three times, with backoff between runs (5 and 10 s by default), then the document ends `failed` with `model_unavailable`              | Automated test (fake model answering 503; three embedding calls)                                                                                         |
| The embedding model returns a vector missing, twice for one position, of the wrong size, or not numbers                                              | The document ends `failed` with `model_bad_output`                                                                                                 | Automated tests                                                                                                                                          |
| `EMBEDDING_DIMENSIONS` set and the model returns another size                                                                                        | `model_bad_output`; documents are recorded as `name@size`, so changing the size counts as a different model                                        | Automated test                                                                                                                                           |
| Model hits its token cap, returns non-JSON or the wrong JSON shape, and so does the thinking-off retry                                               | The answer ends `failed` with `model_bad_output`; the conversation is free for the next question                                                   | Automated tests                                                                                                                                          |
| Model answers 200 without any choices, or `answered` with an empty answer, and so does the thinking-off retry                                        | `model_bad_output`; an empty note on `not_in_document` is accepted                                                                                 | Automated tests                                                                                                                                          |
| Model text holding a NUL character or half an emoji (a lone surrogate)                                                                               | NULs are removed and the half emoji replaced before anything is stored, so the result can always be written                                        | Automated tests                                                                                                                                          |
| Model answers 500, 429 or 400                                                                                                                        | `model_unavailable` (500, 429) after three attempts, or `model_rejected` (400) at once; the conversation is free                                   | Automated tests. By hand, 2026-11-24: a real Gemini 400 through the `openai` package is classified `model_rejected`                                      |
| Model never replies or times out                                                                                                                     | After the thinking-off retry times out too, the job runs again; after three attempts, `model_unavailable`                                          | Automated test (a fake that never replies, 1 s timeouts, six calls). By hand, 2026-11-24, before step 3a: Gemini's free tier did not answer within 240 s |
| A quote that isn't in the passages sent                                                                                                              | Dropped; with no quote left the answer is `unsupported` and hidden                                                                                 | Automated tests (quote matcher and full flow)                                                                                                            |
| The document doesn't cover the question                                                                                                              | `not_in_document` with the model's note (at most 300 characters), no quotes                                                                        | Automated test; real runs on both models                                                                                                                 |
| A second question while one is pending                                                                                                               | 409 `answer_pending` (unique index, no race)                                                                                                       | Automated test                                                                                                                                           |
| A question before the document is ready, or for a document embedded by another model                                                                 | 409 `document_not_ready` or `embedding_model_changed`                                                                                              | Automated tests                                                                                                                                          |
| A question about a document whose preparation failed                                                                                                 | 409 `document_failed`                                                                                                                              | Automated test                                                                                                                                           |
| An answer job for a turn that is already final or on a newer attempt                                                                                 | Does nothing; the model is not called                                                                                                              | Automated test                                                                                                                                           |
| While the model is answering, a newer attempt starts or the turn is marked failed                                                                    | The old job's answer is not recorded                                                                                                               | Automated tests, one per guard condition                                                                                                                 |
| The document changes between accepting a question and answering it                                                                                   | The answer fails with `document_not_ready` or `embedding_model_changed`                                                                            | Automated test (the job's own checks)                                                                                                                    |
| A quote found in a chunk that starts in an earlier section                                                                                           | Labelled with the section it is actually in                                                                                                        | Automated test                                                                                                                                           |
| Redis unreachable when uploading or asking                                                                                                           | 503 `queue_unavailable`; the new row is removed, so nothing is stuck and the conversation stays free                                               | Automated tests (queue pointed at a closed port)                                                                                                         |
| A job whose row is gone (removed after a 503, or a late add)                                                                                         | The job does nothing                                                                                                                               | Automated test                                                                                                                                           |
| The worker is stopped mid-answer                                                                                                                     | Before step 3a: it finished the job if it could within 20 s, then exited 0. Now: see step 3a                                                       | By hand, 2026-11-24                                                                                                                                      |
| The worker is stopped mid-answer and the answer takes longer than 20 s                                                                               | Before step 3a: the job was cut off and handed out again as stalled after a restart. Now: see step 3a                                              | By hand, 2026-11-24: completed 154 s after the restart                                                                                                   |
| A prompt larger than the model's context                                                                                                             | LM Studio refuses it with 400 ("exceeds the available context size") rather than cutting it; the app tells this 400 apart by its message (step 3a) | By hand, 2026-11-24, calling LM Studio directly; not run through the app (step 3 shrinks the passages and retries)                                       |
| A cancelled model request                                                                                                                            | LM Studio stops generating                                                                                                                         | By hand, 2026-11-24                                                                                                                                      |
| Postgres drops the worker's connections while it waits for the model                                                                                 | The answer is still recorded on a fresh connection                                                                                                 | Automated test                                                                                                                                           |
| The model server is off when a document is uploaded                                                                                                  | Preparation runs three times, with backoff between runs, then fails with `model_unavailable`                                                       | Automated test with a fake answering 503; by hand, 2026-11-24, before step 3a, when it failed at once                                                    |
| Search: a passage found by both searches, a keyword match against a closer vector, a question with only stop words, a passage too big for the budget | Ranked first; the keyword match wins; vector ranking alone; skipped while smaller ones still fill the budget. Passages go out in document order    | Automated tests (`search.test.ts`)                                                                                                                       |
| `#` lines inside a fenced code block                                                                                                                 | Treated as code, not as headings, so section labels stay right                                                                                     | Automated test                                                                                                                                           |
| An unknown id on any route                                                                                                                           | 404 `not_found`; a malformed id gives 400                                                                                                          | Automated test, on all seven routes that take an id                                                                                                      |
| Redis restarts while a job runs                                                                                                                      | Expected: the worker reconnects and BullMQ hands the job out again as stalled                                                                      | Not verified                                                                                                                                             |

Not handled yet, on purpose (later steps own them):

- Rows that can be left unfinished. Step 3a's sweeper now finds each of these (see below):
  - a job that stalls twice is failed by BullMQ, and its row stays `pending` or `processing`;
  - Postgres down when a job claims its row or records a result or failure: the row stays `queued`, `processing` or
    `pending`;
  - the removal after a 503 fails too (Postgres down at that moment): a `queued` document or a pending turn that
    locks its conversation is left behind;
  - the worker cut off at its 20 s shutdown limit while it writes a result can leave the row `pending`;
  - the API stopped between saving a row and adding its job: the row stays `queued` or `pending`, with no job;
  - Redis losing an accepted job: it writes its log to disk once a second, so a crash can lose the last second.
- Retry endpoints, idempotency keys and back-pressure: step 3b.
- Upload hardening beyond the checks above, and prompt-injection defences beyond the boundary tag: step 4.
- Live progress: step 5 (clients poll `GET /messages/:id` until then).

## Step 3a: failures in the worker

| Case                                                                                                                        | What happens                                                                                                                                                                                                      | Verified                                                                                                                       |
| --------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| The model hits its token cap, returns no JSON, or takes longer than its timeout                                             | One retry with thinking off; the turn records `thinking_off_retry` as its path                                                                                                                                    | Automated tests, one per case                                                                                                  |
| The thinking-off retry is unusable too                                                                                      | `model_bad_output`                                                                                                                                                                                                | Automated test                                                                                                                 |
| The thinking-off retry times out too                                                                                        | The job runs again after a backoff, and the next attempt can answer                                                                                                                                               | Automated test                                                                                                                 |
| The model answers 429 once                                                                                                  | The job runs again and answers                                                                                                                                                                                    | Automated test                                                                                                                 |
| The model answers 503 every time                                                                                            | Three attempts, then `model_unavailable`                                                                                                                                                                          | Automated test                                                                                                                 |
| The embedding model answers 503 once while preparing                                                                        | The job runs again and the document becomes ready                                                                                                                                                                 | Automated test                                                                                                                 |
| A passage too long for the embedding model                                                                                  | `internal_error`: chunks are far below its limit, so this is a bug                                                                                                                                                | Automated test                                                                                                                 |
| The prompt is too long for the model's context                                                                              | Sent again with half the passage budget; quotes are checked against the passages of that second call. Too long again: `context_too_long`                                                                          | Automated tests                                                                                                                |
| A follow-up question                                                                                                        | Rewritten by the model (thinking off) into a standalone search query; the answer call still gets the question as asked                                                                                            | Automated test                                                                                                                 |
| The rewrite is unusable or times out                                                                                        | Search uses the previous question and the new one together                                                                                                                                                        | Automated tests, one per case                                                                                                  |
| The rewrite meets a server that is down or overloaded                                                                       | The job runs again                                                                                                                                                                                                | Automated test                                                                                                                 |
| The worker is stopped mid-answer                                                                                            | The model call is cancelled and the job goes back to the queue without spending an attempt; the next start answers it                                                                                             | Automated test. By hand, 2026-11-24: `docker compose stop worker` took 0.6 s, exit code 0 (no job running)                     |
| An answer runs past its time limit (10 minutes a run by default)                                                            | The job ends with `model_unavailable` at once, without another run                                                                                                                                                | Automated test (with a 1.5 s limit; one model call)                                                                            |
| A job running for a long time                                                                                               | Touches its row every 15 s; the sweeper leaves alone rows touched in the last 2 minutes, by a heartbeat or otherwise                                                                                              | Automated tests (the heartbeat moves; fresh rows and rows with a recent heartbeat are left alone, for documents and questions) |
| A document or question whose job was lost (any cause in the step 2 list above)                                              | After 2 minutes untouched, the sweeper queues it again under a new attempt, at most twice, then `failed` with `max_attempts`                                                                                      | Automated tests, for both, including the cap                                                                                   |
| A row whose job is still waiting its turn                                                                                   | Left alone, however long it waits                                                                                                                                                                                 | Automated tests, for documents and questions                                                                                   |
| Redis unreachable during a sweep, or the new job can't be added                                                             | The sweep stops at the first error and no requeue is counted. A row whose job couldn't be added keeps its new attempt, so a job that lands late still runs; otherwise the first sweep after 2 minutes moves it on | Automated tests, for documents and questions                                                                                   |
| A job BullMQ fails after it stalled twice                                                                                   | BullMQ doesn't run our code for it; the sweeper finds the row and its failed job, and treats it like a lost one                                                                                                   | The lost-job path is tested; a real double stall is not verified                                                               |
| A wrong model name or a rejected setting at start                                                                           | The worker logs it as an error and `/ready` reports `misconfigured`; a model server that is off shows `unavailable`; `/ready` stays 200 either way                                                                | Automated tests. By hand, 2026-11-24: with the LM Studio server stopped, `/ready` showed both models `unavailable`             |
| A reply with an empty body, or one cut off half way                                                                         | Empty: like an unusable reply (thinking-off retry). Cut off or unreadable: like an outage (the job runs again)                                                                                                    | Automated tests                                                                                                                |
| A reply whose text isn't a string, an embedding reply with an empty body or a missing item                                  | Like an unusable reply: the answer gets the thinking-off retry; preparation fails with `model_bad_output`                                                                                                         | Automated tests                                                                                                                |
| The worker is stopped while a document is being embedded, an embedding call times out, or a preparation runs past its limit | Put back without spending an attempt; run again; `model_unavailable` at once, as for answers                                                                                                                      | Automated tests                                                                                                                |
| The model check is off (`MODEL_STARTUP_CHECK=false`)                                                                        | The worker clears any result an earlier run left, so `/ready` shows none                                                                                                                                          | By hand, 2026-11-24: worker restarted with the check off, `/ready` showed `"model": null`                                      |
